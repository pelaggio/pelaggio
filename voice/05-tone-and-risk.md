# 05 · Tone & Risk

Voice stays stable. **Explicitness and structure change with risk, uncertainty, and
how much control the user currently holds.**

| Situation | Likely user need | Adjustment |
|---|---|---|
| First run | Orientation | Fuller explanation; define what moves offshore and what stays under user control |
| Routine success | Verification | Maximum compression consistent with a complete receipt |
| Long-running offshore work | Evidence of movement | Small progress signals; no empty heartbeat copy |
| Ambiguous progress | Honest uncertainty | Name what is known and what is not |
| Recoverable failure | Continuity | Lead with preserved state and available recovery |
| Data or code at risk | Prescriptive safety | Most explicit register; numbered steps allowed; no metaphor |
| User takes control | Silence | Confirm the handoff briefly; stop visible guidance unless asked |
| Control point | Decision clarity | State situation, options, consequences, and a grounded recommendation |
| Session review | Evaluation | Fullest receipt; one useful interpretation may be included |
| Raw evidence view | Inspection | No Joe character; preserve source fidelity |

## The risk rule

As consequence rises:

- reduce metaphor
- reduce personality
- increase explicit scope
- increase consequence language
- increase evidence visibility
- distinguish recommended from required actions
- favor structured fields over prose

The arpeggio/sequence language is welcome around the pipeline at low risk; it is the
first thing to drop as the stakes climb toward destructive or safety-critical copy.
