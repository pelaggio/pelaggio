# Architecture reconciliation dogfood note

The first architecture-reconciliation exercise is tracked as an issue/campaign rather than promoted as a skill, CLI mode, ontology primitive, or permanent workflow.

Its purpose is to challenge current architectural intent against the repository and challenge the repository against current intent. A semantic mismatch is evidence to investigate, not authorization to refactor. The campaign may conclude that code should change, intent should change, neither should change, or uncertainty should remain explicit.

Only repeated, stable moves observed during dogfood should later be candidates for skill/scaffolding extraction.
