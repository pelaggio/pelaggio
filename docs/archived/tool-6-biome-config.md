## Approach

**Why Biome over ESLint + Prettier**: Roadmap prescribes it; Biome is a single binary, zero-config by default, fast, and we're linting a ~1700-line corpus — ESLint's plugin tax isn't justified. Biome 2.x is the current release line; whatever `pnpm add -D @biomejs/biome` pulls in is the version we target.

**Why scope to `scripts/` only**: The rubric explicitly says Biome should stay scoped to `scripts/`. Skill markdown, templates, and roadmap docs are prose, not code.

**Why lefthook over Husky**: Roadmap prescribes lefthook. Lefthook is also a single binary, runs hooks in parallel by default, and has first-class support for running commands only on staged files with `{staged_files}` templating. Husky would need `lint-staged` glue for the same behaviour.

**Why `--write` in the pre-commit hook**: Auto-formatting on commit is the low-friction path — developers don't see spurious hook failures for whitespace issues they didn't notice. Combined with lefthook's `stage_fixed: true`, the fixes land in the same commit. The hook still fails hard on lint errors (unfixable diagnostics) so real problems surface.

**Interaction with the autopilot checkpoint commits**: `helpers.ts:97` already passes `--no-verify` to `git commit` for checkpoints. That bypasses lefthook entirely, so the pipeline can keep checkpointing mid-step without risk. `/ship` commits do *not* use `--no-verify` — that's intentional. The ship commit runs through biome, which will pass because (a) the implementation pass already ran `biome check --write`, and (b) the hook autofixes anything that slipped.

**Line width 240**: The existing code has lines up to **237 characters** — the worst offender is `pipeline.ts:415`, a `console.log` with a deeply-interpolated template literal (`cycles`, `parallel`, `budget`, `PR mode`, `[DRY RUN]` all strung together). Next worst: `tui.ts:389` at 205 chars (step-footer `ln()` call). After that: `step-runner.ts:3` at 156 (six-identifier type import), `helpers.ts:7/52/180` in the 151–154 range (JSDoc + long execSync strings), and **`config.ts:43–44` at 143 chars each** — the `MODEL_PROFILES` records the original draft of this plan specifically tried to protect.

Biome defaults to 80. Reformatting to 80 — or even 140 as a first draft tried — would reflow the `MODEL_PROFILES` records (breaking them across multiple lines per profile, destroying the step-per-column readability) and the two long log lines. 240 covers the observed max with a small buffer, preserves every existing line exactly as-is, and still catches pathological 300+ char lines. The rubric already says "concise" and "no premature abstractions"; `lineWidth` is a *safety net*, not a style hammer, and fighting 50 lines of existing code for a round number would violate the "whitespace / punctuation / import-ordering only" rule the Files-to-change table sets.

## Concrete config contents

### `biome.json`

```json
{
  "$schema": "./node_modules/@biomejs/biome/configuration_schema.json",
  "files": {
    "includes": ["scripts/**/*.ts"]
  },
  "formatter": {
    "enabled": true,
    "indentStyle": "tab",
    "indentWidth": 1,
    "lineWidth": 240
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "double",
      "trailingCommas": "all",
      "semicolons": "always",
      "arrowParentheses": "always"
    }
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "suspicious": {
        "noExplicitAny": "error"
      },
      "style": {
        "useImportType": "error",
        "noNonNullAssertion": "off"
      }
    }
  },
  "assist": {
    "enabled": true,
    "actions": {
      "source": {
        "organizeImports": "on"
      }
    }
  }
}
```

**Field-by-field rationale:**

- `files.includes` (not `files.include`): Biome 2.x renamed this. If `pnpm add` happens to install 1.x, swap to `files.include`. Verify against `node_modules/@biomejs/biome/configuration_schema.json` after install — the plan's only load-bearing schema check.
- `indentStyle: "tab"` + `indentWidth: 1`: matches current code (`helpers.ts:1` onward uses literal tabs).
- `quoteStyle: "double"` + `trailingCommas: "all"` + `semicolons: "always"`: all three are already how the existing code is written. Biome defaults already match; listing them is defensive against future default shifts.
- `noExplicitAny: "error"`: the rubric mandates "No `any`". Biome catches this so the rule is enforced mechanically, not only by review.
- `useImportType: "error"`: nudges toward `import type { ... }` for type-only imports. `step-runner.ts:3` and `helpers.ts:5` already use it correctly; the rule keeps future code consistent.
- `noNonNullAssertion: "off"`: `helpers.ts:207–209` uses `!` assertions on `parts.find(...)!.value` for `Intl.DateTimeFormat` output. The code is correct — DateTimeFormat always emits those parts for the requested options — and rewriting it would add noise. Disabling the rule is cheaper than restructuring.
- `assist.actions.source.organizeImports: "on"`: replaces the legacy `organizeImports` top-level key, which was moved in 2.x. Sorts imports deterministically: node builtins → external → local paths, matching the rubric's "Imports order" invariant.

### `lefthook.yml`

```yaml
pre-commit:
  parallel: true
  commands:
    biome:
      glob: "scripts/**/*.ts"
      run: pnpm exec biome check --write --no-errors-on-unmatched {staged_files}
      stage_fixed: true
```

- `glob: "scripts/**/*.ts"` ensures the command only runs when staged files actually match — commits that touch only markdown skip the hook entirely.
- `{staged_files}` + `stage_fixed: true` is lefthook's canonical pattern for "format staged files, then re-stage the fixes". Any auto-fix lands in the same commit.
- `--no-errors-on-unmatched` guards against `glob` pre-filtering paths in a way that leaves Biome with an empty arg list (`biome check` with zero files exits non-zero otherwise).
- `pnpm exec` over bare `biome` so we don't depend on `node_modules/.bin` being on PATH (it isn't, inside a fresh clone before the first `pnpm install` is run).
- `parallel: true` is a no-op today (one command) but costs nothing and is idiomatic for future hooks.

### `package.json` additions

```json
{
  "scripts": {
```

- `prepare` runs automatically after `pnpm install`, so fresh clones get hooks without a manual step. If a developer disables lifecycle scripts, hooks simply aren't installed — no error, just no protection, matching lefthook's intended graceful-degradation behaviour.
- Exact installed versions come from `pnpm add -D @biomejs/biome lefthook`; the carets above are placeholders — record whatever `pnpm` picks.

## Test strategy

No new unit tests — Biome config is declarative and a lint test would just re-run `biome check`.

**Verification gates** (all must pass before commit):

1. `pnpm install` completes cleanly and installs `@biomejs/biome` + `lefthook`.
2. `pnpm exec lefthook install` installs hooks into `.git/hooks/` (runs via `prepare`).
3. `pnpm check` exits 0 — the repo is clean after the one-shot `biome check --write` pass.
4. `pnpm test` (existing) still passes — no behavioural drift from reformatting.
5. The rubric's listed commands still succeed:
   - `npx tsx --test scripts/autopilot/__tests__/helpers.test.ts`
   - `npx tsx -e "import('./scripts/autopilot/config.ts')"`
   - `npx tsx -e "import('./scripts/autopilot/helpers.ts')"`
   - `npx tsx -e "import('./scripts/autopilot/pipeline.ts')"`
6. **Hook smoke test**: introduce a deliberate formatting violation (e.g., single quotes in a local file), `git add`, `git commit`, and confirm the hook autofixes + re-stages without aborting the commit. Then revert the probe so the final diff is clean.
7. **`--no-verify` path still works**: run `pnpm autopilot --dry-run --cycles 1` and confirm checkpoint commits (if any) bypass the hook as expected. Dry-run is sufficient — no SDK calls required to exercise `checkpoint()`.

## Self-review — issues caught, and revisions

**First-pass issues I found re-reading this plan critically:**

1. **`-w` in `pnpm add`**: roadmap text says `pnpm add -D -w @biomejs/biome`. This repo has no `pnpm-workspace.yaml`, so `-w` will error. → *Fixed above*: plan drops `-w`.
2. **Biome 2.x vs 1.x schema drift**: `files.include` became `files.includes`, and `organizeImports` moved under `assist.actions.source`. → *Fixed above*: plan uses 2.x shape and explicitly notes the fallback if `pnpm add` pulls 1.x.
3. **Existing code would fail `biome check` on import ordering and possibly `noNonNullAssertion`**. → *Fixed above*: plan includes a one-shot `biome check --write` during implementation and disables `noNonNullAssertion` with a documented reason.
4. **`/ship` pre-commit surprise**: ship commits don't use `--no-verify`, so a dirty biome state would abort ship. → *Resolved*: the one-shot format + hook autofix means ship-time commits should always be clean. Noted in Approach.
5. **Fresh-clone hook installation**: without `prepare`, users would need to remember `pnpm lefthook install`. → *Fixed*: plan adds `prepare: "lefthook install"`.
6. **`pnpm check` name collision**: I first assumed `pnpm check` was safe; verified package.json has no existing `check` script. ✅ no collision.
7. **Line width**: first draft said `100`, second draft said `140` based on an eyeballed max of 154 chars. A proper `awk 'length > max' scripts/**/*.ts` scan showed the real max is **237** (`pipeline.ts:415`), with `MODEL_PROFILES` records in `config.ts` sitting at **143** — meaning 140 would have reflowed the very records the plan was trying to protect. → *Fixed above*: `240`, with rationale tied to the measured 237-char max and a small buffer.
8. **The "Biome is not configured" note lives in two places**: CLAUDE.md *and* `_rubric.md`. → *Fixed*: plan updates both and calls out the trap.
9. **Pre-commit hook arg semantics**: first draft used `--staged` (a Biome flag that scans staged files itself). That works, but it re-scans *all* staged files, not just the glob-matched ones. Switching to `{staged_files}` from lefthook's template keeps the command aligned with the `glob:` filter, so markdown-only commits don't invoke Biome at all. → *Fixed above*.
10. **`--no-errors-on-unmatched`**: added after noticing that `biome check` with zero files exits non-zero, which would surface as a spurious hook failure on commits where lefthook's glob pre-filter leaves no matches. → *Fixed above*.

All revisions are already folded into the body of this plan above. What you're reading *is* the revised plan.
