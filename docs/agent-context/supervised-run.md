# Supervising an autopilot run (operator runbook)

This is the procedure for an **agent or human supervising an end-to-end Pelaggio run out-of-band** — starting a cycle, watching it to a PR, reviewing, landing, and cleaning up. It is distinct from the per-step pipeline skills (`pick`/`plan`/`shakedown`/`ship`), which run *inside* the autonomous cycle. This runbook runs *about* a cycle. The supervisor invokes the mechanisms below and adjudicates their evidence; it never hand-edits a tracked item worktree.

It owns only the **out-of-band delta**: driving a cycle by hand and landing it via an admin path. For the mechanics of each step, defer to `ship`, `pr-review`, and `roadmap-and-ship.md`.

> Many steps below are workarounds for a current gap, tagged **(until …)**. As the CLI absorbs each one, delete that step — this runbook should shrink over time, not grow.

## Procedure

1. **Prune worktrees first.** `git worktree prune`. A stale review-head worktree makes the confinement audit fail. (until worktree GC is automatic — see `tidy`.)
2. **Run the cycle.** `pnpm pelaggio --item <N> --cycles 1`; watch it to a PR. Do **not** pass `--verbose` on supervised runs — supervise from the out-of-band station/logs instead. With `review.authoring.enabled: local`, a piped or backgrounded invocation (`| tee`, `&`) has no interactive TTY and the review gate refuses; prefix the command with `PELAGGIO_OPERATOR_ATTENDED=1` to attest attendance — the suppression is recorded in the cycle log, and it never overrides the CI, daemon, or multi-cycle signals. On a transient `529`/`Overloaded`, `pnpm pelaggio --resume <N>` (work is checkpointed via `parkExit`; resume re-enters fresh — [ADR-0019](../decisions/0019-checkpoint-restart-not-replay.md)).

When an adversarial-review escalation is resolved `proceed`, inspect the committed resolution and evidence, then resume with the exact fingerprint printed by the park message: `pnpm pelaggio --resume <N> --acknowledge-escalation <fingerprint>`. A missing or mismatched acknowledgement parks again, and `resolved-block` cannot be acknowledged through.
3. **Pass — roll the gate once on the shipped SHA.** Confirm `git rev-parse HEAD` in the item worktree equals the PR head. Use the terminal gate result already produced for that SHA by the local runner; if none exists, run `npx pelaggio pr-review --pr <N>` once from the run's **main checkout** (not from the item worktree). This command is effectful: it upserts the gate comment and posts the required `review` status. If it passes, continue to landing. If it is red, keep that result as the fix input; do not repeatedly re-review to chase `survivors=0`.
4. **Fix — send every repair through the harness.** From the run's main checkout, run `npx pelaggio revise --pr <N>`. It fetches the typed findings and runs the findings-driven implementation path in the claim worktree; the supervisor never edits that worktree directly. With `review.runner: local`, the revision resumes through `ship` and then automatically drains a full fleet review on the revised SHA before returning. A parked first pass continues with the exact printed `pnpm pelaggio --resume <id> --review-findings <path>` command — do not start a new `revise --pr` pass.
5. **Verify from the worktree.** `pnpm --filter pelaggio test` and `pnpm check`, **run from the worktree** — running from the main checkout tests the wrong code. `pnpm check` trips on stale `.dev/review-heads/*`; clear with `git worktree prune`. (until #131/#246.)
6. **Go — use the automatic revised-head gate.** Confirm the PR head still equals the revised worktree `HEAD`, then use the terminal local-runner result for that SHA. If it passes, continue to landing. If it is red, that revised-head result is the next fix input: after inspecting the first repair, run one deliberate `npx pelaggio revise --pr <N> --allow-repeat`; the repeat also ends with an automatic full review of its shipped SHA. If that second repair is still red, park for the human under the escalation defaults below.

   Do **not** run `pr-adjudicate` after `revise` in this local-runner flow. The original and revised fleet reviews are both retained as per-SHA evidence, and `pr-adjudicate` deterministically refuses when a PR has multiple fleet records. Do not launch an extra `pr-review` either: `revise` has already rolled the full gate on the revised head.
7. **Land.** With the unpinned-`review` + `ship.target: auto-merge-pr` posture (see `docs/pr-review.md#alternative-local-review-auto-merge-unpinned-review`), landing is automatic once `ci` and `review` are green — skip this step and step 8; supervision is retrospective. The admin path below applies only if the `review` app-pin is (re)enabled. `--admin` **bypasses branch protection**, so it is an out-of-band exception, not the standard path ([ADR-0003](../decisions/0003-pr-gated-by-default.md), ADR-0005). Use `npx pelaggio land --pr <N> --repo <owner/repo> --admin` rather than a raw `gh pr merge --admin`: it reads the PR's CI status directly and refuses to merge (exit 1, with a diagnostic) unless every check has completed green — deterministic, not operator discipline (issue #292). `--admin` is required only because a local-subscription review posts as `app=None` against a branch-protection pin (in this repo, GitHub app id `15368` — environment-specific, may change) — it bypasses the *review-pin*, **never** the CI-green requirement. Because the admin path also skips the pipeline's post-merge tail, you must run step 8 (mark-done) and confirm post-merge verify by hand. The guard degrades to CI-green-alone until the ADR-0018 attestation (#188) lands; it never fails open. (`--admin` bypassing the review-pin is why the path is temporary — until the review posts under the pinned app; see `roadmap-and-ship.md`.)
8. **Mark done.** After an admin merge, `npx pelaggio roadmap mark-done <N>` — an admin merge bypasses the pipeline's post-merge mark-done, so the issue otherwise stays open. (Admin PR merge never runs the direct-push bookkeeping tail; #205's claim-branch retention only covers direct-push mark-done failure, not this path.)
9. **Clean up.** Remove the worktree; sync main via a **rebase-pull that preserves any concurrent session's unpushed local commits** (`git pull --rebase`; never fast-forward-discard or reset).

   If a failed run or closed PR is being abandoned while its issue stays open, releasing its claim is four ordered acts: close the PR; remove the worktree **before** deleting its checked-out branch; delete both local and remote claim branches; then remove the issue's `in-progress` label (`gh issue edit <N> --remove-label in-progress`, until the roadmap CLI supports claim-label release). Omitting the label removal leaves an open issue permanently invisible to `roadmap next`; deleting the branches alone is not a complete release (#422).

## Concurrent human work

Don't inspect, fix up, or otherwise edit files inside the main checkout or a claimed item worktree while a cycle holds it. The confinement audit snapshots main plus every registered sibling worktree before, periodically during, and after each step (`pipeline.md`); a concurrent edit is indistinguishable from a real violation, and a mid-step trip now fails the cycle closed with an early abort rather than parking it (#388) — a park would checkpoint the now-contaminated tree, and `--resume` re-enters "fresh" onto it, re-burning spend against state already proven compromised (see [ADR-0019](../decisions/0019-checkpoint-restart-not-replay.md)).

All operator-authored work — chartering, plan authoring, config edits, document review, investigation, and fixups — belongs in a **separate `git clone`**, not merely reviews and fixes and never a second `git worktree add`. A worktree registers with `git worktree list` and becomes a new sibling the running cycle's audit tracks, while a plain clone has its own independent `.git` the audit never enumerates. The `pr-review` / `revise` invocations above still run from the run's main checkout because they resolve and guard the live claim worktree; invoking those mechanisms does not authorize a hand-edit there. Only touch the live worktree once the cycle has exited (parked, completed, or errored).

## Escalation adjudication

When the driver pulls the Andon cord ([ADR-0011](../decisions/0011-andon-not-dor.md)) or a review does not converge, the supervisor adjudicates. The defaults:

- **A `blocked` outcome** → allow **one decorrelated retry** of the blocked agent operation (a fresh attempt, on a *different seat/provider where available*). A **second, reproduced block escalates** to the human; do not turn it into repeated gate rolls or revision passes. If no alternate provider is configured the retry is **same-seat and correlated** — treat a second same-seat block as *weaker* evidence and prefer escalating rather than trusting the re-run. `missing-decision` / `external-dependency` kinds — which a retry cannot resolve — escalate on the first block.
- **A safety-class finding that survives** → never self-clear it with a supervisor `proceed`. An authoring `resolved-block` remains unacknowledgeable; a PR-gate finding must be repaired through `revise` and independently re-verified by the automatic full review of the revised head. If it still survives after the one deliberate repeat above, never merge; park for the human. This is a deterministic gate, not a tolerance setting ([ADR-0016](../decisions/0016-severity-taxonomy-and-owner.md)).
- **A judgment-band dissent** → accept or park per the project's tolerance policy ([ADR-0015](../decisions/0015-autonomy-by-default-configurable-tolerance.md)) and record the Judge's reasoning. An accepted authoring `proceed` only resumes the pipeline; it does not green the eventual PR head, which still follows the pass-fix-go flow above. Tolerance never authorizes a direct status override or a hand-edit.
- **A transient rate-limit / outage** → `--resume`, do not abort.

Under [ADR-0015](../decisions/0015-autonomy-by-default-configurable-tolerance.md), a fully-automated supervisor may merge when the deterministic gates pass and the reasoned decision is recorded; the human is pulled in only by a deterministic-gate trip or a reproduced block.
