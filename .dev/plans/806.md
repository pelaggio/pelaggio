# Plan: fail-closed macOS Claude Seatbelt preview

## Scope

Deliver an opt-in macOS Claude-seat preview. It will retain the existing unconditional
provider seam: a Claude SDK child starts only after a platform-specific seat preflight
succeeds, and failures remain `error_confinement`. The preview will use a native Seatbelt
launcher with a new process session, deny the same harness-only socket and forge-denied
GitHub-config directories that Linux Bubblewrap masks, and produce an operator-shareable,
scrubbed local conformance report.

This change does not make macOS support the default, add an unconfined fallback, claim a
general container boundary, restrict the model-provider network, or make a macOS CI job
required before a maintained runner exists. Linux Bubblewrap arguments and behavior remain
unchanged.

DECISION: Preview opt-in placement | chose: a Claude-specific boolean under
`providers.claude` | alternatives: automatic macOS enablement; a generic unsandboxed
fallback | The boundary is provider-specific and only Claude has this preview. Automatic
enablement would make an unevidenced platform claim; an unsandboxed flag violates the
fail-closed seat invariant.

## Approach

1. Refactor `packages/pelaggio/scripts/pelaggio/claude-seat.ts` around one discriminated,
   platform-neutral seat result/invocation contract. Keep shared authority classification,
   environment filtering, protected-path validation, credential-directory discovery,
   stderr scrubbing, and preflight orchestration in this module. Move Linux-specific
   Bubblewrap discovery and argv construction behind the Linux arm rather than copying
   them into the provider.

2. Add the macOS arm only when the explicit preview configuration is enabled. Discover a
   trusted absolute `sandbox-exec` launcher, construct a Seatbelt profile from structured
   path grants/denials (never interpolate unchecked paths), and launch it detached so the
   child has a fresh session/process group. The policy grants the worktree and minimum
   runtime/auth locations required by Claude, while deny rules precede/generalize over
   harness socket parents and denied-role GitHub configuration directories. Validate and
   reject missing, shared, malformed, or too-wide paths before profile construction.

3. Make preflight execute zero-spend canaries through the selected invocation: visibility
   and connection denial for a harness-only socket parent, denied credential/config read
   for non-forge roles, required worktree/runtime access, and distinct session identity.
   Return typed probe outcomes that can be rendered as a scrubbed diagnostic report. A
   failed, unavailable, or inconclusive probe remains a confinement failure and never
   reaches `query()`.

4. Extend configuration parsing and documentation for the explicit preview switch and
   diagnostic command. State that reports have no repository paths, credentials, prompt
   content, or automatic upload; they are operator-submitted evidence. Keep current
   non-Linux refusal if the switch is absent, and document that unattended/CI macOS usage
   remains unsupported until runtime evidence is sustained.

5. Add a macOS-only workflow/test entry that runs the runtime conformance test when the
   runner is available, but does not weaken the current Linux CI gate. Keep pure policy,
   invocation, configuration, environment, and failure tests runnable on Linux with fake
   launchers; guard actual `sandbox-exec` execution by `process.platform === "darwin"`.

## Files to change

- `packages/pelaggio/scripts/pelaggio/claude-seat.ts`: own the discriminated platform
  selection, invocation builders, preflight canaries, detached spawn behavior, and
  diagnostic projection; retain shared path/authority/env logic here as the single
  chokepoint.
- `packages/pelaggio/scripts/pelaggio/providers/claude.ts`: thread only the resolved
  configuration into existing `preflightClaudeSeat` and `spawnClaudeSeat` calls; do not
  introduce platform branching or a fallback here.
- `packages/pelaggio/scripts/pelaggio/config.ts` and its config tests: parse a
  Claude-only explicit macOS-preview option, default false, reject wrong provider/type,
  and expose it through `ResolvedConfig`.
- `packages/pelaggio/scripts/pelaggio/__tests__/claude-seat.test.ts`: cover the common
  contract and both platform argv/profile builders with fake process execution, including
  path rejection, deny precedence, detached launch, all canary failure modes, and no
  unwrapped invocation.
- `packages/pelaggio/scripts/pelaggio/__tests__/claude-seat-macos.test.ts` (or a clearly
  named macOS-only section in the existing file): exercise real Seatbelt canaries on macOS
  and skip elsewhere without treating a skip as evidence.
- `.github/workflows/ci.yml`: retain Linux test coverage and add a separately identifiable
  macOS conformance job only once it can be provisioned safely; avoid making a hosted
  preview test a required status until it is stable.
- `docs/config.md`, `docs/trust/sandboxing.md`, `docs/trust/trust-claims.yml`, and the
  macOS operator documentation: describe the preview, exact guarantees and limits,
  fail-closed behavior, and manual scrubbed-report collection without overstating support.

## Test strategy

- Run focused `claude-seat` and `config` node:test files after each implementation slice,
  then the full Pelaggio test glob with the dot reporter.
- On every platform, assert that configuration defaults preserve the present behavior;
  macOS preview false, unsupported platform, missing launcher, malformed policy input,
  and failed probe all stop before SDK `query()`.
- Assert generated Linux invocations are byte-for-byte unchanged. For macOS, assert the
  structured profile includes only normalized grants, denies protected directories before
  broad grants, and invokes no shell.
- On macOS, run real no-network/no-token canaries for socket connection/read denial,
  GitHub-config denial in a forge-denied role, worktree allowed access, and new-session
  identity. Emit a versioned, path-scrubbed report only on explicit local command use.
- Run `pnpm check`, `pnpm typecheck`, `pnpm typecheck:ratchet`, `pnpm check:trust`, and
  relevant documentation checks before handoff. A macOS test skip on Linux is not a pass
  for the platform claim.

## Rubric self-check

- Correct: one `claude-seat.ts` chokepoint owns the guarantee across both platforms;
  `providers/claude.ts` remains unconditional and no configuration can select an
  uncontained child. The claimed inputs are harness socket locators, known GitHub config
  directories, environment filtering, platform launcher/profile construction, and session
  identity; this item owns the seat seam, while CI-runner promotion is explicitly deferred.
- Well-typed: use discriminated platform/preflight/invocation results rather than optional
  `bwrap`-style fields or booleans that could imply a fallback.
- Well-factored: share policy discovery and validation; only the native execution grammar
  belongs in each platform builder.
- Well-tested: pure builders run everywhere; real Seatbelt assertions require macOS and
  are clearly separated from skips.
- Concise: no general sandbox framework, telemetry service, credential broker, or
  provider-wide configuration abstraction is introduced.
