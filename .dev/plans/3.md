# Plan — Issue #3: Multi-repo web UI (registry-driven repo selector)

> Source: cdhorne/claude-autopilot#3 — depends on #2 (merged).

Surface the multi-repo registry shipped in #2 in the web UI. Nav dropdown
driven by `GET /repos`, persisted selection in `localStorage`, per-repo
runs / roadmap / stats views, repo slug badged on run detail.

## Scope

**In scope** (web only, plus a tiny server-side type catch-up):

- `lib/api.ts` — drop unprefixed `getRoadmap()` / `getStats()` (the daemon deleted those routes); add `listRepos()`, `getRoadmap(slug)`, `getStats(slug)`; require `repo: string` in `StartRunBody`; expose `repo: string` in `StartRunResponse`.
- New `lib/repo.ts` — module-level current-repo store (mirrors the `lib/token.ts` shape) with a `useCurrentRepo()` hook over `useSyncExternalStore`.
- New `components/RepoNav.tsx` — nav-bar React island, dropdown of repos, persists selection on change.
- `components/RunList.tsx` — filter by current repo via `?repo=`; "all repos" toggle (ephemeral, per-tab) groups by repo.
- `components/RunDetail.tsx` — badge `run.repo` next to id/status.
- `components/StartForm.tsx` — read current repo from store; refetch roadmap when it changes; pass `repo` in `startRun()`.
- `components/StatsView.tsx` — same: read current repo; refetch on change.
- `layouts/Base.astro` — render `<RepoNav client:load />`; clear-token script also clears the repo-selection key.
- `astro.config.mjs` — proxy `/repos` to the daemon in dev.
- `packages/server/src/types.ts` — add `repo: string` to `RunSummary` (the runtime data already includes it); inline `RepoEntry` shape from the route into `types.ts` so the web client can import it. Annotate `summarize()`'s return as `RunSummary` to keep it honest.

**Not in scope** (deliberate):

- Cross-repo dashboards / aggregated stats (issue's explicit non-goal).
- Repo-scoped tokens (issue's explicit non-goal).
- Editing the registry from the UI (operator's job — `~/.config/autopilot-server/repos.yml`).
- Cross-tab sync via `storage` events (overkill — selection changes are user-driven and rare).
- Server route changes — `/repos`, `/repos/:slug/roadmap`, `/repos/:slug/stats`, `POST /runs.body.repo`, `GET /runs?repo=` all already exist.
- Component tests — the web package has no JSDOM/RTL setup; convention is unit tests for utilities and manual smoke for components. Don't expand the test surface here.

## Approach

The reshape mirrors the daemon-side reshape from #2: the UI is now repo-aware at one shared chokepoint (the current-repo store), with three consumers (RunList, StartForm, StatsView) reading from it and one writer (RepoNav). Run detail just badges the slug it already has on the `PersistedRun` record.

### Why a module-level store, not React context

Astro's island model means each `client:load` boundary is its own React tree — a `<RepoProvider>` in `Base.astro` would not propagate context across islands. But every island imports the same JS module, so a module-level pub/sub trivially shares state. This is exactly the pattern `lib/token.ts` already uses (handler registry + cache), so the precedent is in-repo and proven.

`useSyncExternalStore` is the React 18+/19 idiom for subscribing to a module store. It avoids the stale-closure pitfalls of `useState + useEffect`, and React's concurrent rendering uses the `subscribe` / `getSnapshot` shape directly. One `useCurrentRepo()` hook wraps it; consumers don't see the plumbing.

### Store shape — discriminated union over nullables

```ts
type RepoState =
  | { status: "loading" }
  | { status: "empty"; repos: readonly RepoEntry[] }   // registry has zero entries
  | { status: "ready"; repos: readonly RepoEntry[]; current: string };
```

The three states map cleanly to three render branches in each consumer (one `switch (state.status)`), instead of nested null checks across `repos === null` / `repos.length === 0` / `!currentRepo`.

`current` is always a slug present in `repos`. Initialization logic:

1. Fetch `/repos` once on first hook subscription (idempotent — module caches the in-flight promise).
2. Read `localStorage["autopilot-current-repo"]`.
3. If stored slug appears in the fetched list → use it.
4. If stored slug is stale (registry edited since) → use first entry; overwrite localStorage to match.
5. If list is empty → `{ status: "empty", repos: [] }`. localStorage untouched.

`setCurrentRepo(slug)` validates the slug is in the current list, writes to localStorage, advances state, notifies subscribers. Unknown slug throws (defense — the dropdown can't produce one).

### Why "all repos" is a *toggle*, not a third dropdown option

The acceptance bullet reads `Runs list filters by current repo; "all repos" toggle groups by repo` — separate verbs. Treating "all" as a third selectable repo would conflate "what I'm working on now" (persisted, drives StartForm + StatsView) with "what I want to see in this list" (per-tab view mode). A local checkbox in `RunList` keeps the toggle ephemeral and out of the global store.

When toggle is off → `listRuns({ repo: currentRepo })` (server-side filter via `?repo=`). Flat table.

When toggle is on → `listRuns()` (no filter). Group client-side by `r.repo`. Render one `<tbody>` per repo with a section header row, in the order the repos appear in `/repos` (registry order is stable per `loadRegistry`).

### Race-condition handling

The existing components use a `cancelled` flag in `useEffect` to discard in-flight responses on unmount. The new effects that depend on `currentRepo` follow the same pattern, with `currentRepo` in the dep array — switching repos mid-fetch is the new race surface and the existing pattern covers it.

### Server-side type catch-up (one file)

`summarize()` in `routes/runs.ts` already returns `repo`, but `RunSummary` doesn't declare it. The type is wrong today; it just hasn't burned anyone because no consumer reads `r.repo` yet. The web client will, so fix the type. While there:

- Hoist `RepoEntry` from inline-in-route to `types.ts` so the web package can import it via the existing `@cdhorne/claude-autopilot-server/types` subpath.
- Annotate `summarize()`'s return as `RunSummary`. Compiler now enforces the contract.

This is a type-correctness fix, not a behavior change. No test changes required server-side; it just stops the lie. (If preferred, the web client could declare its own copies — but single-source typing across the workspace is the established pattern, and `api.ts` already imports server types.)

## Test strategy

All tests via existing harnesses: `pnpm --filter @cdhorne/claude-autopilot-web test` and `pnpm --filter @cdhorne/claude-autopilot-server test`. Both run `tsx --test __tests__/*.test.ts`.

### Unit — `repo.test.ts` (new)

Pattern matches `token.test.ts` (FakeStorage, `__setStorageForTests`). Inject a fake `fetcher` so tests don't hit the network.

- **default selection (no stored)**: with `repos: [a, b]` and empty localStorage → `state.current === "a"`; localStorage written to `"a"`.
- **default selection (valid stored)**: localStorage `"b"`, repos `[a, b]` → `current === "b"`; localStorage unchanged.
- **default selection (stale stored)**: localStorage `"gone"`, repos `[a, b]` → `current === "a"`; localStorage overwritten to `"a"`.
- **empty registry**: `repos: []` → `state.status === "empty"`; localStorage untouched.
- **setCurrentRepo persists + notifies**: subscribe a spy, `setCurrentRepo("b")` → state updates, spy called once, localStorage now `"b"`.
- **setCurrentRepo rejects unknown**: `setCurrentRepo("missing")` throws (with the slug in the message); state unchanged; localStorage unchanged.
- **subscribe returns working unsubscribe**: call unsubscribe, then `setCurrentRepo("b")`; spy not called again.
- **init dedup**: call `init()` twice concurrently with a slow fetcher; assert fetcher invoked once; both promises resolve to the same state.

### Unit — `api.test.ts` (updated)

- `listRepos()` → URL is `/repos`, parsed body returned. (Exact mirror of the existing `listRuns` test.)
- `getRoadmap("foo")` → `/repos/foo/roadmap`.
- `getRoadmap("ns/with-slash")` → `/repos/ns%2Fwith-slash/roadmap` (encoding regression — slugs aren't expected to contain slashes but defending against bad data is cheap).
- `getStats("foo")` → `/repos/foo/stats`.
- `startRun({ repo: "main", item: "X", parallel: 2 })` → body `JSON.stringify({ repo: "main", item: "X", parallel: 2 })`.

Drop the unprefixed `/roadmap` and `/stats` test cases entirely — those routes are gone from the daemon.

### Server-side — no test additions

The type fix in `types.ts` is enforced by `tsc` (via `astro check` on the web side and `tsx` runtime checks on the server). No new behavior.

### Manual smoke (per acceptance bullet 6)

1. Add a second repo to `~/.config/autopilot-server/repos.yml`, restart `systemctl --user restart autopilot-server`.
2. `pnpm --filter @cdhorne/claude-autopilot-web dev` → open http://localhost:4321/ui/.
3. Confirm nav dropdown shows both repos. Reload — selection persists.
4. Switch to repo A → `/ui/start/` → roadmap loads from repo A → start one cycle. Repeat for repo B.
5. `/ui/` shows only the current repo's runs. Toggle "all repos" → both visible, grouped by repo with section headers.
6. Click a run → run detail page shows `repo: <slug>` badge. SSE log streams correctly.
7. `/ui/stats/` shows current-repo stats. Switch repos → stats refresh.
8. Click "clear token" in nav → token cleared, repo selection cleared, page reloads, token prompt appears, dropdown re-resolves to first entry.
