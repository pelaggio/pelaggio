## Implementation

1. Extend the optional PR findings contents with typed qualification (code/contract/judgment/check reference), recommendation, limitations and material questions. Maintain schema-v1 legacy report compatibility and fingerprint/gate semantics. Keep PR-only additions out of the shared authoring-v3 wire grammar. Parse optional qualification separately from the existing blocking fields: malformed optional detail is unavailable with a diagnostic, never a new approval or a new blocker; malformed existing blocking fields retain their current fail-closed behavior. Models cannot author harness check results. Attribute conclusions to actual seats and bind them to reviewed SHA; an unavailable check stays unavailable.
2. Add compact assessment and answer records using registerPath/writeJsonAtomically at the durable main root. Preserve all assessment generations and answer supersession using a separate uniquely named immutable file per generation/answer, not read-modify-write of a shared aggregate: writeJsonAtomically replaces its destination and supplies neither append semantics nor concurrency exclusion. Register the new store as harness-owned in REGISTERS. Explicit supersedes references must resolve to the same task/question lineage; reject unknown or cyclic references. A question ID derives from its statement and declared relevant paths, namespaced by PR/item. Scope answers to the original task digest, question, assessment and relevant path object IDs. Require explicit supersedes for replacements; concurrent conflicting descendants remain visible and inapplicable. Never infer resolution from omission.
3. Provide an operator CLI for answers and read-only rendering/SARIF export. Require explicit source revision, actor and response; retain original request. At first assessment, snapshot the configured roadmap item through RoadmapSource, retaining source identity and exact original text/digest; reuse that snapshot on revision and reassessment instead of silently replacing it with a later mutable issue body. Standalone PRs without a resolvable item must supply explicit task input or render task context as unavailable. Clarification changes task interpretation only; it never grants tool, publication or merge permission. Use the existing host-operator/register boundary, document that actor is operator-supplied attribution, not authenticated identity. Do not invoke adjudication, status publication or merge. Do not consume mutable store input under an untrusted provider pool.
4. Thread original intent and applicable answers into findings-driven implement and cold discovery/verification inputs. Keep prior verdicts and Judge briefs out of cold discovery. Preserve stale/conflicting/unanswered residuals in assessment history. Bind assessments to the actual inputs used, not a later read of the store. Freeze task/answer input once before seat launch and pass that same value through retries, verification and persistence. Snapshot applicable input again only for a new assessment. Preserve per-seat qualifications when deduplicating gate candidates so disagreement and attribution are not overwritten by the canonical fingerprint.
5. Add renderer and SARIF 2.1.0 projection: stable fingerprint, location and severity; namespaced rich-record reference, explicit loss note; no confidence/rank/suppression-as-fixed. Validate fixtures with the official schema using existing Ajv infrastructure. Apply existing public-output eligibility/redaction at the rich-record rendering and SARIF boundary too; optional model text must not bypass withheld parse diagnostics or expose retained privileged-seat material. Omitted/non-code results and unavailable information are visible loss notes, never invented locations or results.
6. Supply deterministic simulated-seat scenario through production parser, writer, answer CLI, prompt handoff, actual configured check and renderer. Execute the check through the trusted revision/check harness seam, never by extending the PR discovery seat to execute untrusted PR-head commands (trustedLocalContext currently expressly forbids that). Bind observed command, exit status and output reference to the checked revision; store absent or mismatched receipts as unavailable/stale without claiming success. Capture JSON/Markdown/SARIF and refresh commands for the site consumer. Attempt an attended provider smoke through the harness; if unavailable, label it unverified and make no autonomous-behavior claims.
