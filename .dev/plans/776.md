# Plan: Complete and harden Local Autopilot Contract v0 (#776)

## Outcome

Repair the two-PR stack so the prerelease has one truthful contract and one
black-box-proven consumer path. PR #777 remains the contract layer; PR #778 remains
the implementation and publish layer. A foreign repository can start, inspect,
resume, and cancel a durable Run without path escape, duplicate lifecycle mutation,
repeated acknowledged work, or an overstated execution-safety promise.

## Scope

**PR #777:** complete the four-operation object-root schema surface; make schema and
runtime validation agree by construction; encode lifecycle/readiness invariants;
repair assurance CI; document compatibility and transport semantics.

**PR #778:** validate every public input; contain derived paths; serialize Run and
request mutations; make journal recovery fail closed; implement real interruption and
repair; add truthful host-execution consent; complete help, diagnostics, evidence,
packed tests, and prerelease checks.

**Out:** #751 Case/attestation, MCP, telemetry upload, team installation, automatic
push/PR/merge/release/deploy, portfolio scheduling, and a general CLI rewrite.

## Settled author decisions

`DECISION: preview execution boundary | chose: permit uncontained host execution only through --allow-host-execution or explicit uncommitted execution.mode: host policy; report the effective assurance in every result | alternatives: silently default to host execution; block the preview on contained-provider integration`

Host mode is the documented prerelease path, but never a silent safety claim. Without
the flag or policy opt-in, an unavailable contained mode refuses before repository
mutation. `--non-interactive` never prompts. Human output warns once; JSON output
records `execution.mode`, `contained`, and `effectsEnforced`. `ready_for_review` means
verification/readiness passed, not that the harness was contained. ADR-0029 and README
must replace “effects denied by default” with this precise preview contract. Pelaggio's
own push/PR/merge/release/deploy operations remain absent in both modes.

`DECISION: verification | chose: a verification command is required before ready_for_review | alternatives: treat missing verification as success; add a weaker unverified success disposition`

Missing verification is a configuration error in v0. No new disposition is added.

`DECISION: CLI names | chose: retain top-level run/resume/show/doctor for v0 and expose cancel consistently | alternatives: pelaggio local run/status/resume/cancel/doctor namespace`

`DECISION: non-interactive behavior | chose: retain --non-interactive, carry it into harness policy, and prove it never prompts | alternatives: remove it; add an interactive decision-answer protocol`

No further author adjudication is required for the reviewed findings.

## Approach

### 1. Establish one contract authority in PR #777

- Extend `schemas/v0.schema.json` with object-root inputs for `getRun`,
  `continueRun`, and `cancelRun` (sharing a `runIdRequest` definition), named
  success/problem output roots, the doctor result, and execution-assurance fields.
- Encode `pauseReason` iff paused, `disposition` iff completed, and the deterministic
  readiness rule with JSON Schema conditionals. Add the smallest explicit blocking
  status needed; never infer blocking from problem prose or type.
- Replace the independent structural parser with schema-backed validation. Prefer
  committed Ajv standalone validators generated from the normative schema, plus types
  derived with the already-locked `json-schema-to-ts`, so the packed runtime does not
  carry Ajv. Retain small handwritten lifecycle transition checks only.
- Add a generation/check command that regenerates into a temporary location and fails
  on drift. Specify whether additive output fields are preserved; preserve them across
  parse/re-emit boundaries.
- Update ADR-0029 for explicit host-mode consent, required verification, and execution
  assurance. Regenerate the assurance projection and fix its exact expectation so
  #777 passes `pnpm test:ci` independently.

Files: schema, `types.ts`, `parse.ts`, `lifecycle.ts`, `transport.ts`, a focused
generator, fixtures/tests, schema CI, ADR/context docs, and assurance artifacts/tests.

### 2. Put identifiers and paths through one contained resolver

- Parse a complete `StartRunRequest` before `startRun`; validate run-ID requests before
  show/resume/cancel. Engine exports validate too because future transports may bypass
  the CLI.
- Replace raw `join(base, id)` helpers with one resolver that validates the opaque-ID
  grammar and proves the resolved target is a direct child of the intended base. Apply
  it to run directories, journals, leases, request indexes, and worktree writes,
  including symlink-aware checks before writes.
- Convert parser, config, filesystem, and argument failures into versioned Problem
  objects. JSON mode always emits one schema-valid object and the documented exit code.

Files: `local-autopilot-cli.ts`, `engine.ts`, `paths.ts`, `run-worktree.ts`,
`transport.ts`, and adversarial packed tests.

### 3. Make Run mutation and recovery atomic

- Add one `withRunLease(cwd, runId, fn)` chokepoint. Continue/resume, drive,
  checkpoint, cancel, and terminal completion append only while holding it. Contention
  returns a typed retryable result rather than throwing.
- Give request deduplication an ID-scoped atomic claim using `O_EXCL` or the existing
  lock. Equal concurrent requests converge on one Run; unequal content conflicts; a
  failed start cannot leave an index pointing to a missing journal.
- Validate journal identity, initial event, contiguous increasing sequence, legal
  transitions, and terminal uniqueness during fold. A corrupt/truncated final append
  yields an inspectable protocol problem, never derived success.
- Flush bounded journal records and specify/test partial-final-record recovery. Ensure
  cancel racing drive cannot later become `ready_for_review`; completed Runs are
  immutable and cancellation is idempotent.

Files: `engine.ts`, `journal.ts`, `fold.ts`, existing lock helpers if necessary, and
concurrency/corruption tests.

### 4. Implement truthful host execution, interruption, repair, and evidence

- Add `execution.mode: host|contained` config and `--allow-host-execution`. Resolve the
  effective mode before mutation. Host mode is valid only after explicit flag or local
  policy consent and records `{mode:"host", contained:false,
  effectsEnforced:false}`. Contained mode remains the future stronger path and refuses
  visibly when unavailable.
- Keep Pelaggio-owned external effects absent. Warn that host Grok retains the user's
  ambient capabilities; do not describe prompt instructions as enforcement.
- Thread `AbortSignal` into adapter calls. SIGINT terminates and awaits the child/process
  group, then checkpoints once under the lease and returns paused/interrupted with exit
  130. Resume keeps the Run ID.
- Replace the Grok cursor shortcut with explicit attempt state. Each failed verification
  sends bounded structured failure context to a new harness call; `maxRepairs` counts
  real calls. Persist acknowledgement only after the corresponding event is durable.
- Carry `nonInteractive` into `HarnessContext`; approval or judgment requests become a
  typed pause and stdin prompting is impossible in that mode.
- Require configured verification. Store its bounded result as a digest-addressed
  artifact and require successful evidence plus no open blocking finding for
  `ready_for_review`.

Files: config/schema, `harness.ts`, `grok-adapter.ts`, `engine.ts`, `fold.ts`,
presenters, adapter fixtures, and engine/packed tests.

### 5. Make the five-command CLI strict and reassuring

- Keep Node `util.parseArgs`; do not add a framework. Define routing, usage, examples,
  option sets, and positional arity once so help and dispatch cannot drift.
- Add command-specific `--help`, exact-one diagnostics for file/text/stdin, rejection
  of extra positionals and mixed pipeline/local flags, typed parse failures, and a
  routed/documented `cancel` command.
- Present disposition, verification evidence, assurance mode, worktree/branch, exact
  inspect command, and exact resume/cancel command in action order. Progress uses
  stderr; JSON stdout remains one object.
- Expand README with doctor-first setup; minimal Grok policy; host-mode warning and
  consent; file/text/stdin; decision and verification pauses; exit codes; JSON;
  review/cleanup; platform limits; and a prerelease warning.
- Preserve cold-start dependency restoration before every route and update its test for
  the declarative router without weakening the invariant.

Files: `bin/pelaggio.js`, `local-autopilot-cli.ts`, `present.ts`, package README,
context docs, and packed CLI tests.

### 6. Prove the installed artifact

- Install the packed tarball into a clean temporary repository and invoke its installed
  bin rather than the source-tree bin.
- Cover success with verification evidence; invalid config before mutation; every input
  form; strict arity/help; JSON errors; decision pause; real repair count/exhaustion;
  harness crash; in-flight SIGINT/resume; cancel-vs-drive; concurrent request IDs; path
  traversal/symlink attempts; corrupt/truncated/reordered journals; source-checkout
  preservation; absence of Pelaggio-owned external effects/telemetry; truthful host
  assurance; metrics exclusions; and exact package allowlist.
- Share adapter contract tests between fake and Grok test doubles so the fake cannot
  model a different cursor/abort/repair protocol.
- Run `pnpm check`, `pnpm check:skills`, `pnpm check:publish`, `pnpm -r test`, and
  `pnpm test:ci` on each stack layer. #777 must be green alone; #778 must be green on
  #777. Run one bounded real-host-Grok acceptance only with explicit consent.

## Implementation order

1. Amend #777: schema surface, generated validation/types, lifecycle conditionals,
   contract docs, fixtures, and assurance/check repair; then rebase #778.
2. On #778, land input validation/path containment with regression tests.
3. Add request/Run serialization and journal recovery validation.
4. Add explicit host assurance, real cancellation/repair, non-interactive behavior,
   and verification evidence.
5. Finish CLI help/presentation/docs and the installed-tarball suite.
6. Run all checks independently on both layers and publish only when required acceptance
   cases pass.

## Test minimality

- Schema generation owns structural agreement; lifecycle tables own state transitions;
  path tests own containment; lease tests own concurrency; adapter contract tests own
  attempt/abort semantics; packed tests own wiring, output, and packaging.
- Keep one authoritative test per invariant and only a small packed smoke matrix proving
  that seam reaches the shipped bin. Do not duplicate every fixture at both levels.
- Every regression test must fail on the reviewed implementation and name the guarantee
  it locks in.

## Rubric self-check

- **Correct:** covers every confirmed review finding and the charter's missing evidence,
  concurrency, recovery, and installed-artifact cases without claiming host containment.
- **Well-typed:** one schema-derived structural contract with closed request/result,
  execution-assurance, problem, and adapter-action unions.
- **Well-factored:** validation, contained paths, Run mutation, and execution assurance
  each have one chokepoint rather than call-site patches.
- **Well-tested:** adversarial no-false-fire tests at each chokepoint plus a minimal
  installed-tarball acceptance matrix.
- **Concise:** retains `util.parseArgs`, reuses existing locks, removes the duplicate
  handwritten structural parser, and adds no parallel SDK or lifecycle.

## Self-review revision

The original plan treated fixture agreement as proof that independent validators could
not drift, described unrestricted Grok as effects-denied, and listed packed cases that
were not actually exercised through the artifact. This revision hoists the guarantees
to enforceable chokepoints and incorporates the author's explicit preview defaults.
